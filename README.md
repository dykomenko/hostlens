# HostLens: итоги, IP и трафик в кабинетах хостингов

Userscript для [Tampermonkey](https://www.tampermonkey.net/), который достраивает то, чего не хватает
в личных кабинетах хостеров: сколько всё стоит, сколько нужно доплатить, чтобы ничего не отключилось,
а где кабинет не показывает IP и трафик в списке — показывает их.

| Кабинет | Движок | Что добавляется |
| --- | --- | --- |
| `my.senko.digital` | BILLmanager | панель итогов под списком услуг |
| `my.waicore.com` | BILLmanager | панель итогов под списком услуг |
| `my.h2.nexus` | BILLmanager | панель итогов под списком услуг |
| `avoro.eu` | WHMCS | панель итогов под списком услуг **и** IP, трафик и срок оплаты у каждой услуги |
| `portal.cherryservers.com` | собственный портал (Vue) | кнопка «netplan» у каждой публичной IPv4-подсети сервера |

## Панель итогов

Появляется под списком услуг (Виртуальные серверы, Выделенные серверы, Домены и другие списки с ценой
и датой окончания):

| Блок | Что показывает |
| --- | --- |
| **Стоимость в месяц** | Сумма цен всех услуг из списка, приведённая к месяцу |
| **Чтобы всё работало ещё N мес** | Сколько нужно заплатить, чтобы каждая услуга дожила до «сегодня + N месяцев» (1 / 2 / 3 / 6 / 12, выбор запоминается), и ближайшая дата продления |
| **Баланс** | Баланс из шапки кабинета |
| **Баланса хватит до** | Дата первого отключения при текущем балансе, сколько до неё дней и каких услуг не хватит. Если баланса хватает на 3 года вперёд, пишет «✓ 3+ года» |
| **Пополнить на** | «К оплате» минус баланс. Если баланса хватает, пишет «✓ хватает» и остаток |

Кнопка «Подробнее» раскрывает таблицу по каждой услуге: дата окончания, цена, сколько продлений
понадобится и сколько это стоит.

### Как считается «к оплате»

- Для каждой услуги берётся цена за период (`5.00 € / Месяц`, `6,25 EUR Monthly`) и дата окончания.
- Нужное число продлений — сколько периодов надо оплатить, чтобы дата окончания дошла до «сегодня + N месяцев».
  Услуга, которая действует дольше, ничего не требует. Уже просроченная считается от сегодняшнего дня.
  Квартальная или годовая услуга оплачивается целым периодом.
- Услуги со статусом «Удалён», `Terminated`, `Cancelled` пропускаются, разовые платежи в месячную стоимость не входят.
- Баланс вычитается, только если валюта совпадает с валютой услуг.
- «Баланса хватит до»: скрипт идёт по будущим списаниям (каждая услуга списывается в дату окончания и затем раз в период),
  вычитает их из баланса и берёт первую дату, на которую списаний за день больше, чем осталось денег. Это грубая оценка:
  она предполагает, что каждая услуга продлевается автоматически в свой срок, не учитывает пополнения и изменения цен.
  Уже просроченные услуги считаются как списание сегодня.

В BILLmanager считаются строки, которые сейчас загружены в таблицу, поэтому фильтр списка влияет на итог;
если строк меньше, чем в «Всего: N», панель предупредит. В Avoro таблица фильтруется и листается на
стороне браузера, поэтому итоги считаются по свежей копии страницы со всеми услугами.

## Avoro: IP, трафик и срок оплаты в списке

В списке услуг у каждой действующей услуги появляется блок:

- **IP** — все адреса сервера. Клик по адресу копирует его, клик по блоку копирует все.
- **Трафик** — расход с индикатором (зелёный, жёлтый, красный).
- **Оплата** — цена, дата и сколько дней осталось.

IP и трафик скрипт берёт со страницы каждой услуги: до трёх запросов одновременно, результат кэшируется
в `localStorage` (IP на 7 дней, трафик на час). Кнопка ↻ в блоке обновляет данные сразу. В меню
Tampermonkey есть команды «Обновить все услуги» и «Очистить кэш».

## Cherry Servers: подсети для netplan

На странице `…/servers/<id>/network/subnets` (вкладка IPv4) рядом с каждой подсетью появляется кнопка
**netplan**. Она копирует все адреса подсети, которые можно назначить серверу, в виде готовых
пунктов списка `addresses:` (отступ ровно 8 пробелов, без завершающего перевода строки).
Для `203.0.113.8/29` со шлюзом `203.0.113.9` получится:

```
        - 203.0.113.10/29
        - 203.0.113.11/29
        - 203.0.113.12/29
        - 203.0.113.13/29
        - 203.0.113.14/29
```

Рядом вторая кнопка **ubuntu** — тот же список в «ubuntu»-стиле: отступ 6 пробелов и адреса в кавычках:

```
      - "203.0.113.10/29"
```

Третья кнопка **NetPulse** копирует те же адреса через запятую, без маски (`203.0.113.10,203.0.113.11,…`).

Из списка исключаются адрес сети, широковещательный адрес и шлюз (шлюз берётся с карточки подсети;
если его там нет, считается первым адресом после сети). Для IPv6-подсетей кнопки нет.
Клик по кнопке не открывает подсеть.

### Floating IP (`…/servers/<id>/network/floating-ips`)

Портал обрабатывает floating IP по одному, а после каждого действия перезагружает весь список. Над списком
добавляется панель, а у каждой карточки — галочка и кнопки копирования:

- **Все адреса на одной странице:** портал показывает по 10, поэтому у его собственного запроса списка
  (`limit=10` на первой странице) размер страницы меняется на 100, портал сам рисует все карточки, а пагинация скрывается.
  Если адресов больше 100, остаётся обычная пагинация. Панель при прокрутке остаётся сверху.
- **Выбор:** галочка у карточки и «выбрать все» (в пределах того, что показано на странице).
- **Свёрнутые поля:** PTR, DNS, DDoS Scrubbing и Tags скрыты (карточки получаются компактнее). Показать снова:
  меню Tampermonkey → «Floating IP: показать/скрыть PTR, DNS, DDoS, Tags».
- **Attach (N) / Detach (N):** по одному адресу: скрипт нажимает кнопку, ждёт, пока портал покажет именно этот адрес
  выполненным, делает паузу и переходит к следующему. В панели видны счётчик, адрес и полоса прогресса; то, что не
  получилось, получает ещё один проход, а в конце пишется «готово X из N» и список неудавшихся адресов.
- **netplan / ubuntu / NetPulse:** копирует выбранные адреса (если ничего не выбрано — все на странице) в виде `- <ip>/32`
  в том же формате, что и для подсетей; NetPulse выдаёт адреса через запятую без маски. У каждой карточки есть
  свои кнопки netplan и ubuntu.
- **Проектная страница (`…/projects/<id>/network/floating-ips`):** тот же размер страницы (запрос списка с `limit=9`
  становится `limit=100`, вкладка Subnets не затрагивается) и «лёгкий» режим панели: «выбрать все», счётчик,
  список «Выбрать по цели…» («Свободные» и по пункту на каждый сервер, найденный в карточках), копирование
  netplan / ubuntu / NetPulse, галочки и кнопки на карточках. Attach, Detach, Terminate и «Купить» там не показываются.
- **Купить…:** заказывает N адресов подряд (до 20). Перед заказом скрипт читает цену из диалога портала и показывает
  итог в час и в месяц, а покупка выполняется только после кнопки «Подтвердить».
- **Terminate… (N):** удаляет выбранные **неприкреплённые** адреса. Перед запуском нужно нажать «Подтвердить»; скрипт сам
  вписывает фразу подтверждения и никогда не трогает адрес, который сейчас прикреплён.
- **Фраза подтверждения** в диалоге удаления теперь выделяется и копируется кликом, рядом есть кнопка «вставить».
- **Цена в месяц:** рядом с каждой почасовой ценой портала (`0.003 EUR/hr`) показывается `≈ 2.16 EUR/мес` (30 суток).

Скрипт нажимает кнопки самого портала и не обращается к его API напрямую.

Заодно на всех страницах портала на фон добавлен едва заметный узор из полупрозрачных символов казино
(масти, фишки, кубики, семёрки). Он рисуется как `background-image` у `body`, не перехватывает клики и
не влияет на карточки. Выключить и включить обратно: меню Tampermonkey → «Фон Cherry: показать/скрыть».

## Установка

1. Поставьте расширение [Tampermonkey](https://www.tampermonkey.net/).
2. Откройте файл скрипта: **[hostlens.user.js](https://raw.githubusercontent.com/dykomenko/hostlens/main/hostlens.user.js)**
   — Tampermonkey сам предложит его установить. Нажмите «Установить».
3. Откройте кабинет → список услуг.

Если раньше стояли отдельные скрипты «Senko BILLmanager: итоги по услугам» или «Avoro IP + Traffic +
Billing Finder», удалите их: HostLens заменяет оба, и вместе они будут дублировать блоки.

### Другой BILLmanager-кабинет

Панель итогов опирается на стандартную тему BILLmanager (`dragon`), поэтому на других хостингах с таким же
кабинетом она, скорее всего, тоже заработает. Чтобы включить её там, не правя файл (правки затёрлись бы
при обновлении), добавьте адрес в Tampermonkey: скрипт → «Настройки» → «Пользовательские совпадения»
(User matches), например `https://my.example.com/billmgr*`. Навсегда добавить хост в репозиторий — это
одна строка `@match` в заголовке скрипта.

## Автообновление

В заголовке скрипта прописаны `@updateURL` и `@downloadURL` на файл в ветке `main`, поэтому
Tampermonkey сам подтягивает новые версии (по умолчанию проверяет раз в сутки).

Tampermonkey обновляет скрипт, только если выросла `@version`. Чтобы про это не нужно было
помнить, в репозитории есть workflow [bump-version.yml](.github/workflows/bump-version.yml): после
каждого пуша, который меняет скрипт, он прогоняет тесты и сам увеличивает патч-версию отдельным
коммитом `chore: bump userscript version`. Если вы поднимете версию вручную (например, до `2.1.0`
для крупного изменения), workflow ничего не тронет.

> Бот добавляет коммит в `main`, поэтому перед следующим пушем делайте `git pull --rebase`.

Проверить обновление сразу: Tampermonkey → «Утилиты» → «Проверить обновления скриптов»
(или значок расширения → ваш скрипт → «Обновить»). Raw-файл на GitHub кэшируется до пяти минут.

## Приватность

Скрипт не отправляет данные никуда, кроме самого кабинета: на Avoro он запрашивает страницы того же
`avoro.eu` (`@connect avoro.eu`), на BILLmanager и Cherry Servers вообще не делает запросов. В `localStorage`
хранятся настройки (число месяцев, развёрнута ли таблица) и кэш IP и трафика Avoro. Все расчёты идут
в браузере по данным, которые уже есть на странице.

## Разработка

```bash
node --test test/core.test.js
```

Разбор цен, периодов, продлений, IP и трафика вынесен в чистые функции и покрыт тестами. Нужен Node.js 18+.
Если панель или блоки пропали после обновления дизайна кабинета, проверять в первую очередь селекторы:
в адаптерах `runBillmanager` и `runAvoro` они описаны комментариями.
