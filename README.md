# BILLmanager: итоги по услугам (Senko, WAIcore)

Userscript для [Tampermonkey](https://www.tampermonkey.net/), который добавляет в личный кабинет
панель **под списком услуг** (Виртуальные серверы, Выделенные серверы, Домены и другие списки,
где есть колонки «Стоимость» и «Действует до»). Работает на:

- `my.senko.digital/billmgr`
- `my.waicore.com/billmgr`
- `my.h2.nexus/billmgr`

Панель показывает:

| Блок | Что показывает |
| --- | --- |
| **Стоимость в месяц** | Сумма цен всех услуг из списка, приведённая к месяцу |
| **Чтобы всё работало ещё N мес** | Сколько нужно заплатить, чтобы каждая услуга дожила до «сегодня + N месяцев» (1 / 2 / 3 / 6 / 12, выбор запоминается), ближайшая дата продления |
| **Баланс** | Баланс из шапки кабинета |
| **Пополнить на** | «К оплате» минус баланс. Если баланса хватает, пишет «✓ хватает» и остаток |

Кнопка «Подробнее» раскрывает таблицу по каждой услуге: дата окончания, цена, сколько продлений
понадобится и сколько это стоит.

## Установка

1. Поставьте расширение [Tampermonkey](https://www.tampermonkey.net/).
2. Откройте файл скрипта: **[senko-billmgr-totals.user.js](https://raw.githubusercontent.com/dykomenko/senko-billmgr-totals/main/senko-billmgr-totals.user.js)**
   — Tampermonkey сам предложит его установить. Нажмите «Установить».
3. Откройте кабинет → «Товары/Услуги» → «Виртуальные серверы» (или «VPS»).

### Другой BILLmanager-кабинет

Скрипт опирается на стандартную тему BILLmanager (`dragon`), поэтому на других хостингах с таким же
кабинетом он, скорее всего, тоже заработает. Чтобы включить его там, не правя файл (правки
затёрлись бы при обновлении), добавьте адрес в Tampermonkey: скрипт → «Настройки» →
«Пользовательские совпадения» (User matches), например `https://my.example.com/billmgr*`.
Постоянное добавление хоста в репозиторий — это одна строка `@match` в заголовке скрипта.

## Автообновление

В заголовке скрипта прописаны `@updateURL` и `@downloadURL` на файл в ветке `main`, поэтому
Tampermonkey сам подтягивает новые версии (по умолчанию проверяет раз в сутки).

Tampermonkey обновляет скрипт, только если выросла `@version`. Чтобы про это не нужно было
помнить, в репозитории есть workflow [bump-version.yml](.github/workflows/bump-version.yml): после
каждого пуша, который меняет скрипт, он прогоняет тесты и сам увеличивает патч-версию отдельным
коммитом `chore: bump userscript version`. Если вы поднимете версию вручную (например, до `1.1.0`
для крупного изменения), workflow ничего не тронет.

> Бот добавляет коммит в `main`, поэтому перед следующим пушем делайте `git pull --rebase`.

Проверить обновление сразу: Tampermonkey → «Утилиты» → «Проверить обновления скриптов»
(или значок расширения → ваш скрипт → «Обновить»). Raw-файл на GitHub кэшируется до пяти минут.

## Как считается «к оплате»

- Для каждой услуги берётся цена за период из колонки «Стоимость» (`5.00 € / Месяц`) и дата из «Действует до».
- Нужное число продлений — сколько периодов надо оплатить, чтобы дата окончания дошла до «сегодня + N месяцев».
  Услуга, которая действует дольше, ничего не требует. Уже просроченная считается от сегодняшнего дня.
- Услуги со статусом «Удалён/Удаляется» пропускаются.
- Баланс вычитается, только если валюта совпадает с валютой услуг.
- Считаются строки, которые сейчас загружены в таблицу, поэтому фильтр списка влияет на итог.
  Если в таблице меньше строк, чем в «Всего: N» (виртуальная прокрутка, пагинация), панель предупредит.

## Приватность

Скрипт ничего не отправляет по сети и ничего не хранит, кроме двух настроек в `localStorage`
(выбранное число месяцев и развёрнута ли таблица). Все расчёты идут в браузере по данным,
которые уже есть на странице.

## Разработка

```bash
node --test test/core.test.js
```

Логика расчёта (разбор цен, периодов, продлений) вынесена в чистые функции и покрыта тестами.
Нужен Node.js 18+.
